# Selecting an investigation rule on configuration and transferring it to dispatch

Eight hand-authored candidate rules vary only the first check (inspect application code or probe the primary source) and the trigger for the second (always, unresolved, observed value differs from primary, never). Every rule has at most two checks; unsuccessful requests count. Accepted evidence is a causal marker or unique attribution from inspected complete dependencies and observations. An opaque source is never named on its value alone.

Train on the full 24-case synthetic scalar configuration grid. Reject any rule with incorrect attribution. Among eligible rules maximize proven correct answers, then minimize checks, then retain earliest enumeration order. Log all candidates and their scores. Write a fresh selection receipt exclusively. A second program audits the training traces and selection before a separate process may import the dispatch fixture. The transfer process must match the previously logged receipt hash. The candidate code, fixture grid, score priorities, tiebreaker and transfer gate are frozen in the commit before GitHub executes the experiment. All fixture code is public; separation is procedural, without a confidential benchmark.

Transfer once to 60 synthetic queue dispatcher configurations: configured mail/batch, cold or resumed startup, empty journal, note-only journal, or multiple events with an earlier superseded resume followed by a last resume to mail, batch or other. The app ignores trailing notes. Open, probe-unavailable and fully opaque conditions are crossed. The two compared policies receive identical initial observations and constraints, and are scored on the winning original file. An isolated process tags each existing effective definition to identify the winning file. Application inspections extract literal filenames from actual source in the fixture grammar. Each domain supplies a purpose-built marker editor (on the dispatcher it modifies the last resume entry). Both methods share this prior knowledge. File-level attribution and unit-cost checks are the scope; learning to write probes or to parse arbitrary programs is outside it.

Compare the selected rule with always inspecting then probing. Success requires zero wrong, at least as many correct, and strictly fewer checks. Record tradeoffs by access condition even when the aggregate criterion passes. Receipt rows contain actual application output, oracle marker, actions and attribution. See the workflow for exact reproduction, including the independently audited training freeze.
